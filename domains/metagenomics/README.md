# Metagenomics domain (Workflomics) — handover notes

## 1) What my goal was
The goal of this domain was to build a **minimal, end-to-end, executable “starter” metagenomics pipeline** for **genome-resolved metagenomics (MAGs)**, because MAG workflows have a clear and testable step sequence:

**QC → assembly → binning → MAG quality evaluation** (completeness/contamination).

This Phase 1 scope was chosen intentionally so the domain could be validated early with APE and later expanded to broader shotgun profiling workflows. 


## 2) What is in this folder
This domain is organized as:

- `config.json`  
  APE domain config: ontology paths, I/O specification (inputs/outputs), synthesis settings, export settings.

- `tools.json`  
  The **selected tool list + semantic annotations** (EDAM data + formats + operations) used by APE.

- `constraints.json`  
  Rules to restrict “nonsense” workflows (e.g., enforce or forbid specific tool connections). 

- `ape_solutions/`  
  Output folder generated by APE (candidate workflows as CWL, figures, and scripts).


## 3) Tools currently included in the metagenomics domain (tools.json)
This domain currently contains **7 tools**, centered around the MAG backbone:

### MAG backbone tools (Phase 1)
1) **FastQC**  
   Read quality control (generates QC reports).

2) **Trimmomatic**  
   Trimming / cleaning paired-end reads (FASTQ → cleaned FASTQ).

3) **MEGAHIT**  
   Assembly (paired FASTQ reads → contigs in FASTA).

4) **MetaBAT2**  
   Binning (uses assembly contigs + coverage/depth information to produce bins).  
   *Note:* the current semantic output type should be reviewed (see “Known limitations”).  

5) **CheckM**  
   MAG quality evaluation (completeness/contamination style report). 

### Supporting tools (already added)
6) **Bowtie2**  
   Mapping reads to a reference (e.g., reads → BAM/SAM alignment).

7) **SAMtoolsSort**  
   Sort alignments (SAM/BAM → sorted BAM).

This tool set is meant to support a MAG-style pipeline, starting from paired-end sequencing reads. 


## 4) Current state: what APE generates right now (where I left it)
APE is working and exporting workflows.

Current `config.json` specification is:
- **Inputs:** paired-end FASTQ reads (**nucleic acid sequences** + FASTQ format)
- **Output:** assembly contigs in FASTA

With that goal, APE returns biologically reasonable **assembly workflows**, and the minimal valid candidate is:

**MEGAHIT-only** (reads → assembly).

Reason: the requested output is assembly FASTA; MEGAHIT alone already satisfies it. No extra steps are required unless the output/constraints demand them.

APE outputs are written to:
`domains/metagenomics/ape_solutions/`

Typical output artifacts:
- `solutions.txt`
- `CWL/candidate_workflow_*.cwl`
- `Figures/candidate_workflow_*.png`
- `Executables/candidate_workflow_1.sh`
- `ape_run.log`

- Java installed
- (Docker is needed later only if you execute CWL with `cwltool`)

## 6) Constraints (current)

constraints.json currently contains lightweight connection logic such as:

- If both tools are used, **MEGAHIT must connect to Bowtie2**  
  (`MEGAHIT → Bowtie2`)
- If both tools are used, **Bowtie2 must connect to SAMtoolsSort**  
  (`Bowtie2 → SAMtoolsSort`)
- If both tools are used, **MetaBAT2 must connect to CheckM**  
  (`MetaBAT2 → CheckM`)
- **MEGAHIT must not connect directly to CheckM**  
  (there must be something in between)

### Why this still does not produce full MAG pipelines
Right now APE is asked to produce **assembly FASTA** as the final output.  
Since **MEGAHIT already produces that output**, APE can return a valid workflow without adding binning or CheckM.

Also, some intermediate files needed for MAG workflows (especially **coverage/depth files** and **bins**) still need more precise EDAM typing. Without that, APE has less information to build the full “assembly → binning → quality check” chain.

## 7) Future steps (what’s needed next)

### 1) Make the domain represent a real MAG goal
A MAG pipeline is not “reads → assembly” only. A complete MAG workflow usually aims to produce:
- **Bins (MAG candidates)**, and/or
- **A quality report** (completeness/contamination)

### 2) Fix / refine semantic annotations (so tools connect correctly)
To get a biologically correct chain, the intermediate data products need correct EDAM typing:

- **MEGAHIT output**: contigs/assembly in FASTA (already done)
- **Mapping output** (Bowtie2): alignments (SAM/BAM)
- **Sorting output** (SAMtoolsSort): sorted BAM
- **Coverage/depth output**: a coverage table/file used by binning tools
- **MetaBAT2 output**: **bins** (not “assembly contigs” again)
- **CheckM output**: a quality **report/metrics** file

Once these are correctly modeled, APE will naturally build:
**QC/trim → assembly → mapping/coverage → binning → quality evaluation**

### 3) Add the missing MAG “glue” tools (recommended)
To make the MAG chain executable and complete, add at least one tool for each missing step:

- **Coverage/depth estimation** (required for binning)
  - e.g., **CoverM** (already available in `cwl-tools/coverm/`)

Common MAG additions:
- **Read filtering / host removal** (for host-associated samples)
- **Assembly QC** (e.g., contig stats / assembly evaluation)

### 4) After the MAG backbone is stable, expand the domain to cover other common metagenomics goals (e.g., read-based profiling and assembly-based annotation).
